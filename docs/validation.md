# Валидация

`Worksheet.write()` выполняет статический анализ, проверку размещения и структуры XML **до открытия выходного файла**. Найденные семантические ошибки вызывают `WorksheetValidationError` (наследник `ValidationError`); существующий файл при такой ошибке сохраняется. Проверки конструкторов по-прежнему могут выбрасывать `TypeError` и `ValueError`, размещение — `LayoutError`.

```python
from xmcd import Symbol, Worksheet, WorksheetValidationError

sheet = Worksheet()
sheet.evaluate(Symbol('missing') + 1, tag='velocity', height=40)

report = sheet.check()                 # Собрать ошибки и предупреждения.
for diagnostic in report.diagnostics:
    print(diagnostic.severity, diagnostic)

try:
    sheet.write('result.xmcd')         # Проверка выполняется автоматически.
except WorksheetValidationError as error:
    print(error.report.errors)
```

Сообщение содержит код, порядковый номер региона в порядке вычисления, `tag` и путь внутри выражения. Вложенные области разворачиваются для анализа; номер диагностического региона не обязательно совпадает с XML `region-id`. `report.errors` и `report.warnings` — кортежи объектов `Diagnostic`, уровень задаёт `Severity`.

## Проверяемые условия

- Доступность переменных и функций в порядке расположения регионов, отдельный первый проход глобальных определений, исключение отключённых регионов.
- Параметры и замыкания пользовательских функций, локальные переменные программ, переменные интегрирования и численного поиска корня. Буквенный индекс является частью имени.
- Число аргументов пользовательских и зарегистрированных встроенных функций, повторяющиеся параметры, вызов числового значения как функции.
- Допустимая левая часть определения; использование локального присваивания, условий, `break` и `continue` в соответствующем контексте; незаполненные поля.
- Структура `Given`–решатель, параметризованные решающие блоки и связанные переменные ОДУ. Минимизация и максимизация допускаются без `Given`.
- Известные размеры матриц при умножении, сложении, `augment`, `stack`, `lsolve`, определителе и векторном произведении. Различаются скалярное произведение векторов и векторизация.
- Известные индексы с учётом `ORIGIN`, выход за границы массива, нецелые индексы и расширение массива присваиванием. Диапазон трактуется как переменная перебора, а не матричный литерал.
- Доказуемое деление на ноль, нулевой шаг диапазона, недопустимые аргументы факториала, нулевая степень корня, основания логарифма 0 и 1.
- Простая размерностная проверка известных единиц: сложение, сравнения, произведения, деление, степени и корни, единица результата, совместимость ячеек матрицы, безразмерные аргументы основных трансцендентных функций.
- Недопустимая геометрия регионов, включая изменения после создания объекта; существующие проверки типов, сериализации графиков, размещения и структуры XML.

Реестр единиц ограничен основными SI и распространёнными производными: `m`, `mm`, `cm`, `km`, `in`, `ft`, `s`, `ms`, `hr`, `kg`, `g`, `A`, `K`, `mol`, `cd`, `Hz`, `N`, `Pa`, `J`, `W`, `V`, `C`, `ohm`, `rad`, `deg`. Анализ размерностей не реализует полную систему единиц Mathcad, аффинные температуры и все правила единиц встроенных функций.

## Исключения и непроверенные вычисления

```python
report = sheet.validate()                         # Исключение при ошибках; вернуть предупреждения.
sheet.validate(warnings_as_errors=True)            # Предупреждения тоже запрещают документ.
sheet.write('result.xmcd', warnings_as_errors=True)
```

`warnings_as_errors` повышает найденные предупреждения до исключения. Отсутствие предупреждений **не является доказательством** отсутствия всех вычислительных ошибок.

Анализатор не заменяет вычислитель. Он подставляет известные простые числовые значения и анализирует деревья функций, но не исполняет циклы, решатели и произвольные математические функции. Сходимость, существование решения, обусловленность, переполнение, особенности интеграла, ветви комплексных функций, доступность внешних файлов и компонентов могут потребовать реального пересчёта. Для решателей, численного анализа, циклов, символьных и непрозрачных вызовов отчёт содержит предупреждения. Ветви и циклы не превращают предположения о значениях в доказанные ошибки. Обрабатываемые `TryCatch` числовые ошибки не блокируют запись.

Проверка доступности имён намеренно строгая и применяется также к обычным математическим регионам. Свободные переменные допускаются при символьном вычислении; для демонстрационного поля без вычисления можно установить `disabled=True`.

## Встроенные функции и расширения вне реестра

Неизвестное имя вызывает ошибку: опечатка в имени функции не должна молча попасть в документ. Для действительно существующей функции или единицы вне реестра анализа передайте явное объявление:

```python
from xmcd import Function, ResultShape, Symbol, ValidationContext, Worksheet

x = Symbol('x')
extension = Function(Symbol('installed_extension'), [x])
context = ValidationContext(functions=(extension,))
sheet = Worksheet()
sheet.evaluate(extension(2), result_shape=ResultShape.scalar())
report = sheet.validate(context=context)
sheet.write('extension.xmcd', context=context)
```

`ValidationContext(symbols=(...), functions=(...))` принимает `Symbol` и `Function`. Он не создаёт определения в XMCD и не устанавливает расширение. Каждое использование такого объявления даёт предупреждение `external-unchecked`; вызывающий код отвечает за наличие имени в целевой среде. Для своих функций обычного документа используйте `sheet.define(...)`.

## XML и реальный Mathcad

`validate(path_or_bytes, schema=...)` остаётся отдельной проверкой структуры **готового XML**; она не запускает семантический анализ Python-модели. Локальный `worksheet30.xsd` можно также передать в `sheet.validate(schema=...)` и `sheet.write(..., schema=...)`. Схемы PTC не включаются в пакет.

`to_xml()` и `to_bytes()` — низкоуровневая сериализация без семантической проверки; используйте `write()` для обычного выпуска документов. `calculation_errors(...)` читает ошибки, сохранённые самим Mathcad после пересчёта, и не предсказывает их.

Нативная проверка: `tests/fixtures/validation/errors-mathcad14.xmcd`, Mathcad **14.1.5.594**. Семь регионов, отвергнутых анализатором, дают ошибки и в Mathcad: неопределённая переменная, число аргументов, размеры матриц, индекс, единицы, деление на ноль и `2.5!`. Контрольные регионы дают скалярное произведение 14 и минимум 3 без `Given`. Исходный генератор намеренно ошибочного документа — `tests/validation_cases.py`; тест сравнивает набор проблемных тегов и сохранённые результаты. Все 14 обычных примеров проходят анализ и запись.

Правило порядка вычисления согласуется с [руководством Mathcad](https://community.ptc.com/sejnu66972/attachments/sejnu66972/PTCMathcad/202385/1/Mathcad%202000%20User%E2%80%99s%20Guide.pdf). Современный [справочник PTC о решателях](https://support.ptc.com/help/mathcad/r12.0/en/PTC_Mathcad_Help/about_solve_block_functions.html) использован как ориентир; поведение классического Mathcad проверяется отдельно нативными образцами.

Повторные вызовы пользовательской функции с одинаковыми абстрактными аргументами используют общий результат анализа. Разные аргументы и контексты проверяются отдельно; каждая различная ошибка функции сохраняет диагностический пример у каждого места вызова. Это позволяет проверять длинные цепочки зависимых функций без экспоненциального обхода.

При [чтении XMCD](reading.md) неизвестные регионы сохраняются и дают предупреждение `opaque-region`. Проверка записи не отключается для импортированного документа.
